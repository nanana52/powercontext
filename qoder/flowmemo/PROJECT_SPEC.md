# FlowMemo 产品与技术规格 v1

## 1. 目标和边界

一个面向学生实验室、小团队与个人的「零碎工作记录 → 可追溯待办 → 周报」工具。核心卖点不是对话模型，而是**PowerContext 记住用户主动保存的写作偏好及项目决策，跨会话复用**。

输入：会议纪要、周记、实验记录（优先纯文本，支持贴入）。输出：待办清单、风险、决策、每周工作汇报。初版不做企业集成、邮箱接入、复杂权限、论文全文 PDF、向量搜索或多 Agent 体系。

## 2. 用户场景

小周从两份会议记录中归纳任务，确认“本项目要先写风险”。隔天浏览器刷新或重新打开，在同一匿名访问者会话中生成周报，能够看到 PowerContext 召回的这条偏好并实际影响报告排列。若记忆服务不可用，UI 明确提示，不伪造。

## 3. 演示事件格式

`fixtures/demo_notes.json` 的记录完全虚构。提示 Qoder 实现基础解析：至少识别 `待办`、`决定`、`风险` 的行标记，支持用户修正；如有可用 Cloud Agent，可优化自然语言抽取，但所有输入必须经过结构校验与可编辑确认，不依赖模型才能跑通。生成周报可用模板完成，不强制调用外部生成模型。

## 4. 功能

- 新建项目、输入/删除笔记、载入演示、导出演示（JSON）。
- 解析并展示任务：标题、负责人、到期日、项目、优先级、状态、原始来源；支持勾选完成、编辑。
- 记录决策与风险，周报包含已完成、进行中、风险、下周计划及来源引用；不凭空编写日期与成果。
- PowerContext 长期记忆：用户主动输入并保存一条偏好/决策；后端返回真正的写入结果；稍后调用 prepare 召回，UI 展示真实状态并在周报顺序/内容中使用。输入“周报先写风险，再写已完成，最后写下周计划”时至少能改变报告章节顺序。
- 一键复制周报/Markdown 下载，能导入示例并完整演示。
- Qoder Sites 可公开访问的落地/工作台同站，包含项目介绍、代码链接、演示截图、使用说明与技术架构。

## 5. 真实技术集成

PowerContext 官方 HTTP：

- 服务端 POST `/v1/scopes`（创建可信 scope；仅服务端完成并绑定访问者）。
- POST `/v1/memory/remember`：`{scope_id,kind:'decision',text,reason}`。
- POST `/v1/context/prepare`：`{scope_id,query,max_bytes:4000}`；`status: ready|empty`，`content` 由官方服务提供。
- 本地健康检查 GET `/health/live`。

服务端 Environment Secrets：`POWERCONTEXT_URL`, `POWERCONTEXT_TOKEN`（如启用鉴权）。绝不在浏览器端请求 PowerContext 服务，也不回传 token。公网站点的 server function 必须访问一个**真实在线并可达**的 PowerContext 服务，不得用临时 localhost 或静态 JSON 替代。

公网未就绪时，公开站点可先展示项目价值和任务/周报核心流程，但记忆功能必须标注未连接，验收上不能算完成技术结合。Qoder 必须继续指导或实施真实的 PowerContext 公开部署方案并写在 RUNBOOK 中。

## 6. 测试与质量

- 每个接口处理错误（400/401/408/429/5xx）并显示明确可恢复提示；采用固定超时。
- 重复点击不得生成重复任务；同条记录有唯一 id；跨项目不能串数据。
- 无模型服务时至少演示 100% 可预测的演示样例解析、周报生成。
- 前端不展示敏感数据、不注入不可信 HTML；每访客默认隔离。
- 构建脚本和依赖完整、项目运行说明从空环境可复现。
- 公开站点无痕访问成功，站点所有按钮可用（至少有明确错误提示）。
- Qoder 开发截图涵盖需求→编码→调试→发布；不使用其它编程代理取代主要代码工作。

## 7. 不能作出的声明

不能凭模拟 fixture 统计声称节省 80% 时间、拥有真实活跃用户；不得把 `200 OK /health/live` 写成记忆真正接通；不得把 Sites 自带 DB/localStorage 冒充 PowerContext 存储。

## 8. 视觉与交互质量

设计语气：安静、清晰、专业的生产力工具，中文排版优先。暖白纸感背景（#F8F6F1）、深青黑主文本（#193C43）、柔和薄荷绿用于成功态（#D5E7DF）、赤陶橘（#D5805D）标记风险，卡片圆角 14~20px。浅色默认，适配 375px 手机与宽屏；不使用花哨渐变、无意义图标墙或模板化假数据统计。

顶栏：项目选择、记忆连接状态和「载入演示」。主工作区：原始记录（左）→ 待办/风险（中）→ 周报（右），窄屏改为步骤式纵向布局。周报顶部显示「基于 X 条记录、Y 个任务、Z 条已召回记忆」，数据必须来自实际运行；若记忆为空则标“未召回”。

重要微交互：复制成功反馈；编辑后保存反馈；真正的 PowerContext 记忆写入成功/失败提示；用户刷新后完整还原任务状态。

### 最小非 AI 解析规则

- 按行读取并规范化全角冒号；`待办：` → task, `决定：` → decision, `风险：` → risk。
- 对演示任务解析中文负责人、`YYYY-MM-DD` 截止日期及优先级，解析不了时存入待确认，不得乱猜。
- `note_id`、原文行号作为可追溯来源；重复导入相同 note 不应产生重复 task。
- 不应将演示文件中的 `expected` 字段直接当作应用运行统计。
